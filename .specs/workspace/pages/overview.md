# Workspace 首页概览页

## 页面定位

总览页负责给工作台用户提供最近操作记录、当前工作上下文与常用入口，是进入 Workspace 后的轻量着陆页。它应更像“活动记录首页”，而不是排班 KPI 仪表盘。

设计原则：如果某个指标不能直接帮助用户判断下一步操作，就不应出现在总览页首屏。当前页面的主要价值是回答“最近谁改了什么、我可以从哪里继续工作”。

## 源码与依赖

| 类型 | 位置 |
|------|------|
| 页面组件 | `src/features/workspace/pages/OverviewDashboardPage.vue` |
| 共享组件 | `WorkspacePageHeader.vue`、`WorkspaceSurface.vue` |
| 数据接口 | `api.workspace.getOverview()` |

## 核心内容

- Continue Where Work Happens：提供进入月度排班、导入导出、校验中心、员工目录的稳定入口。
- Current Context：展示共享 workspace 月份、时区与当前登录身份，帮助用户确认操作上下文。
- Recent Operations：作为页面主体，展示最近工作台操作记录，并支持按模块筛选和页面搜索过滤。
- Error / Loading / Empty：活动记录加载失败、加载中、无记录或无匹配结果时，都应以内联状态表达，不使用夸张空态占据整页。

## 数据边界

- Recent Operations 来自 `/api/workspace/overview?year=&month=` 的 `activity` 字段，并应与共享 workspace 月份保持一致。
- 页面可以基于 `activity.action` 做轻量模块归类，用于筛选、标签和跳转目标；该归类只服务展示，不改变后端审计语义。
- 页面不再把 `stats` 作为首屏主体；除非未来出现明确可行动的聚合字段，否则不应恢复大面积 KPI 卡片。
- 常用入口由前端按 workspace 路由稳定提供，不依赖后端返回固定快捷动作。
- 总览页只负责查看活动与导流，不直接承载细粒度编辑流程。
- 页面内跳转应复用现有 workspace 路由，而不是旁路新入口。

## 交互与呈现建议

- 页面首屏应先展示常用入口与当前上下文，再把最近操作记录作为主体内容。
- 最近操作记录使用表格 / ledger 结构，突出时间、操作者、模块、动作与相关页面入口。
- 模块筛选应保持轻量，不引入复杂查询构造器。
- 活动记录行之间优先使用分隔线和密度控制，不使用每行独立卡片。
- 页面避免大号 readiness score、覆盖热力图、健康指数和装饰性 dashboard 面板。
- 若概览数据为空，页面仍应保留明确的空态与刷新入口，而不是展示结构缺失的半成品页面。

## 维护提示

- 若新增首页卡片或快捷入口，需要同时更新本页 spec 与 `workspace/index.md` 的目录说明。
- 若希望重新引入 KPI 或聚合指标，应先证明该指标能驱动具体操作，否则应放到对应业务页面而不是总览页。
- 若首页开始承载复杂子流程，应拆出独立子文档，而不是持续堆积在本页。
